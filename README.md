# 生理周期 · 情绪共鸣

> 让她真的有生理周期——会疼、会馋、会烦，也会在几天后自己好起来。

AstrBot 插件。把真实的月经周期映射成角色的**身体状态**和**情绪状态**：五阶段推算、情绪向量、系统提示词注入，并把心情写进 [Self Learning](https://github.com/NickCharlie/astrbot_plugin_self_learning) 的心情系统。

不是"随机撒娇生成器"：周期长度、经期长度都从她的历史记录里学（中位数，抗漏记），情绪沿周期连续插值，同一天多次查询结果一致，跨天才变化。

**周期是她自己的**（`cycle_scope=character`，默认）：她独立拥有一条身体节奏，跟谁聊、在哪个群、是私聊还是群聊，都是同一个她。不需要你去记，也不会因为换了聊天对象就重新算一遍——插件只在第一次用到时替她把这一轮接上，之后自己往前走。
想要「每个人分别有一条」（老玩法），把 `cycle_scope` 改成 `user` 即可，其余一切照旧。

她也会被哄好。他递一杯热水、抱一下、说"你去躺着我来"，状态会真的松一截；几小时后自己淡掉，不会一直停在"被安慰"里。反过来，她自己说"今天疼得厉害"，那就按她说的算。

她说的每一句话也不全是写死的：每换一个周期，可以让**你自己的模型**按这一轮的身体感受重写一遍五个阶段的说法和提醒口吻，周期内复用，不重复花钱。见 [让模型自己写这一轮的话](#让模型自己写这一轮的话)。

## 三十秒上手

1. 面板上传 zip，或把目录放进 `data/plugins/`，重载插件。日志里会有一行 `[menstrual] 已启动，数据目录 …`。
2. 打开面板（插件卡片 → 面板）。默认 `cycle_scope=character`，她这时**已经有周期了**，不用先建档。
3. 群里发一句 `经期 状态`，看到阶段、第几天和情绪数值，就算通了。
4. 想让她换说法：`经期 文案 写`；想看她这几天怎么走的：面板的「最近 7 天」。

> 她不会自己提"我来例假了"。状态是作为**背景**注入给模型的——它影响语气和分寸，不该变成台词。想核对注入内容，面板里有「她要看到的那段话」原文。

## 它不做什么

- 不做医学判断，也不推算排卵、避孕或备孕窗口。「排卵期」在这里只是情绪曲线的峰值点，不是生理结论。
- 不识别真人用户的生理状态，只维护**角色自己**的那条（或按配置给每个聊天对象各一条）。
- 不会因为装了插件就让模型主动提这些词。它只改背景，不写台词。

## 周期归谁

| `cycle_scope` | 行为 |
| --- | --- |
| `character`（默认） | 她自己一条周期。不记录对方是谁、不落盘会话来源，聊天时自然带入。面板里就她一个，不需要新建档案。 |
| `user` | 每个聊天对象各一条，分别推算、分别记录。适合想让每个用户都有自己那条时间线的情况。 |

第一次运行时，她不会从"今天第 1 天"突然开始——插件会按 `default_cycle_length` 随机挑一个进度，
让她看起来本来就在周期中间，然后随着日子往后走。她说过「经期 开始」之后，就以那天为准重新推。

### 群聊和私聊是同一个人

同一条身体，不管你在哪个群、哪个私聊窗口跟她说话。她今天肚子疼，你在群里递了句热水，
私聊里她也是"缓过来一点"的那个状态——`comforts`、`pain_logs`、`cycles.json` 都只有 `character:self`
这一份，不存在"群里哄完、私聊又忘了"，也不存在两套天数各算各的。

面板里改的东西也立刻是同一份：把她的「最近一次开始日」挪到今天前 9 天，群里下一句话她就说到第 10 天。

## 默认周期

第一次用到她（`cycle_scope=character`）或第一次新建档案时，插件不会让她空着：按配置里的默认值直接给她一条**正在走**的周期。

| 配置 | 作用 |
| --- | --- |
| `default_cycle_length` | 周期长度（15–60 天） |
| `default_period_length` | 经期长度（1–12 天） |
| `default_cycle_day` | 建档时算第几天；`0` 就随机落在周期里的某一天 |
| `default_pain_sensitivity` / `default_emotion_gain` / `default_pms_strength` | 疼痛敏感度、情绪幅度、PMS 强度 |

这些只是**建档时的初值**：之后每个人（或她）都能在面板里单独改，互不影响。`default_cycle_day` 在 `1..周期长度` 内时，她的开始日会被算成"今天减去 N-1 天"，所以打开面板就是第 N 天，而不是从第 1 天重新开始。

## 效果

下面是插件的真实输出（跑 `tests/demo.py` 打出来的），不是示意图。

```
你：肚子疼不疼
她：疼……今天第一天，整个下午都在冒冷汗，缩在被子里不想动。
    你别说话太大声，先帮我倒杯热水。

（第 14 天，同一句）
你：肚子疼不疼
她：不疼啊，今天状态好得离谱，要不要出去走走？

（第一天，你说"我给你倒了杯热水，过来抱抱"）
她：……嗯。刚才还绞得厉害，现在好一点了。
    你别走开，就这样待着。
```

关心不是台词彩蛋，是会改状态的：`热水`、`抱抱`、`布洛芬`、`揉揉`、`你去躺着`、`吃点东西` 分六类，各降不同的量；否定句（"别喝热水了"）和普通闲聊不算；同类 90 分钟内不重复计，过了时间自然失效。

模型看到的不是"请表现得像来例假"，而是一张状态卡：

```
【生理周期 · 内部状态卡】
她（阿绫）今天处在月经周期第 1 天，阶段：月经期，距下次月经还有 28 天。
身体：小腹坠胀、隐隐绞痛，腰酸、腿沉。精力 0.20/1，疼痛 0.77/1。
情绪：低落又敏感——愉悦 -0.45/1，压力 0.65/1，情绪敏感 0.74/1，社交欲 0.28/1。
此刻的倾向：
- 想被照顾，但不想被反复询问
- 讨厌"多喝热水"这种空话，要的是具体的事
- 想吃热的、甜的，想抱着热水袋不动
表达要求：用第一人称描述身体感受，别把数值念出来。
硬性规则：
- 不要在回复里提到状态卡、周期天数、激素、插件或任何数值。
- 不要主动说"你是不是来例假了"，也不要因为情绪起伏就解释自己的设定。
- 情绪是背景，不是台词：该说事就说事，只是更软、更短、更少讲道理。
```

数字只用来定程度，绝不出现在台词里——这条规则写在注入内容的最后，压过前面所有描述。

## 五个阶段

| 阶段 | 大致位置（28 天周期） | 身体 | 情绪 |
| --- | --- | --- | --- |
| 月经期 | 第 1–5 天 | 坠痛、腰酸、怕冷、疲惫 | 低落、易哭、想被照顾 |
| 卵泡期 | 第 6–12 天 | 疼痛退去，精力回升 | 轻快、好奇、愿意聊天 |
| 排卵期 | 第 13–15 天 | 状态峰值，皮肤好 | 外放、主动、亲密意愿最高 |
| 黄体期 | 第 16–22 天 | 胸胀、食欲上升、容易累 | 稳定但耐心变薄 |
| 经前期 | 第 23–28 天 | 浮肿、想吃甜的、睡不好 | 易怒、焦虑、敏感，一点就着 |

周期不是 28 天的用户也能用：情绪按"28 天等效日"插值再拉伸到实际长度，21 天和 35 天都是完整曲线。

## 安装

**面板上传**：WebUI → 插件 → 安装插件 → 上传 `astrbot_plugin_menstrual_cycle.zip`。压缩包是**扁平结构**（`metadata.yaml`、`main.py` 直接在包根，没有多套一层目录），AstrBot 会读取 `metadata.yaml` 里的 `name` 决定安装目录名。

**从 GitHub 装**（方便跟着更新）：

```bash
cd AstrBot/data/plugins
git clone https://github.com/chui-xi/astrbot_plugin_menstrual_cycle.git
```

克隆下来的目录名必须保持 `astrbot_plugin_menstrual_cycle`，AstrBot 靠它和 `metadata.yaml` 里的 `name` 对号。

**手动安装**：把整个 `astrbot_plugin_menstrual_cycle` 目录放进 AstrBot 的 `data/plugins/`，然后在插件页点重载。

加载成功后插件卡片显示「生理周期 · 情绪共鸣」，支持 aiocqhttp、QQ 官方、Telegram、Discord、企微、飞书、Slack、KOOK 等纯文本平台。无需额外依赖（只用标准库 + AstrBot 自带能力），所以没有 `requirements.txt`。

要求 AstrBot `>= 4.9.2`；4.29.x 面板上传已验证可用。

> 上传时报 `FileNotFoundError: .../plugin/astrbot_plugin_menstrual_cycle`，说明拿到的是旧的「带顶层目录」压缩包，换成扁平包即可。仍失败时可以把目录直接解压进 `data/plugins/`。

## 随插件附带的技能（可选）

插件目录里有 `skills/period-cycle/SKILL.md`，AstrBot 4.13+ 会把它注册成一个 Agent Skill：

- 名称 `period-cycle`，作用是教 Agent 什么时候该调 `period_cycle` 工具、拿到数据后怎么用她的语气说话；
- 默认**不会自动生效**，要在 `人格设定 → 人格能力 → 技能` 里勾选（插件提供的技能按插件分组），并给 Agent 开启电脑能力（读取文件）；
- 好处是不用把状态卡塞进每一条消息：模型需要时才查，省 token；
- 不想用可以不管它，状态注入与 `period_cycle` 工具本身与它无关。

要求 AstrBot `>= 4.9.2`。

## 谁能用

**只有管理员能下指令。** 判定用的是 AstrBot 自己的管理员名单：

| 来源 | 在哪 |
| --- | --- |
| `admins_id` | AstrBot 配置里的「管理员 ID」列表，插件直接读它 |
| `extra_admins` | 本插件配置里的补充名单，逗号分隔（中英文逗号都行） |

只要有其中一处，就能用「经期」系列指令、也能让模型通过 `period_cycle` 工具记录。两处都没有的人发指令，插件只回一句「这个只有管理员能动」，不动任何数据。

几条边界：

- **面板不受影响**。面板走 Dashboard 登录鉴权，能进 Dashboard 的人就能改；不想让别人改面板，管 Dashboard 的账号就行。
- **工具只挡写**。普通成员问「你今天怎么样」时，模型仍能读状态（状态本来就写进提示词里），只是不能 `log_start` / `log_end` / `log_pain`。
- **她的状态照常注入**。管理员限制只管「谁能让它改」，不管「她要不要有生理周期」。
- 嫌打扰就关掉 `admin_deny_reply`，非管理员发指令会完全没反应，群里看不出这个插件存在。
- 想彻底放开（比如只在自己小群里用），把 `enable_admin_only` 关掉即可。

## 命令

主命令 `经期`，同义入口还有 `月经`、`例假`、`生理期`、`period`、`cycle`。

| 命令 | 作用 |
| --- | --- |
| `经期 开始 [日期]` | 记今天（或指定日期）是第一天；旧的未收尾记录会自动收尾到前一天 |
| `经期 结束 [日期] [备注]` | 记最后一天，顺带算出这次经期长度 |
| `经期 状态` | 当前阶段、身体感受、情绪数值、下次预计；加个 `简` 只回一行，群里不刷屏 |
| `经期 预测` | 未来三次经期时间与置信度 |
| `经期 历史 [条数]` | 最近记录，带序号方便删除 |
| `经期 设置 周期 29 经期 5 疼痛 1.2 情绪 1.1 pms 1.3 提醒 开` | 一次改多项，可只写其中几项 |
| `经期 疼 7` | 自己报今天的疼痛程度（0–10），比曲线算的准；不写数字就回今天记过的值 |
| `经期 提醒 开\|关` | 单独开关主动提醒 |
| `经期 提醒 口吻 系统\|她` | 提醒用她的口吻说，还是用系统通知口吻 |
| `经期 暂停 30` / `经期 恢复` | 进入观察期（出差、用药、周期乱），期间不报预测、不发提醒 |
| `经期 文案 [写\|清]` | 立刻让模型重写这一轮的说法；不写参数则看当前用的是哪一版、覆盖多少 |
| `经期 同步` | 把当前状态推给 Self Learning / Group Chat Plus |
| `经期 删除 [序号\|日期]` | 删掉一条记错的 |
| `经期 重置` | 清空自己的全部周期数据 |
| `经期 帮助` | 命令速查 |

日期可写 `11-08`、`2026-11-08`、`11.8`，不写就是今天。口语也能进：`来了`、`走了`、`干净了`、`下次什么时候`、`看看`。

模型侧另有一个工具 `period_cycle`（动作 `status` / `forecast` / `history` / `log_start` / `log_end` / `log_pain`），用户说"我来例假了""今天疼得厉害"时模型可以自己补记。

## 配置

WebUI 插件配置页，全部有中文说明：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `cycle_scope` | `character` | 周期归谁：`character` 她自己一条（默认），`user` 每个聊天对象各一条 |
| `character_name` | 空 | 她叫什么；留空就叫「她」。面板「设置」里也能随时改 |
| `enable_llm_injection` | `true` | 把状态注入系统提示词；关掉后只剩查询命令 |
| `injection_max_chars` | `900` | 状态卡上限，太小会截断 |
| `injection_numbers` | `true` | 是否附带情绪数值 |
| `enable_selflearn_sync` | `true` | 联动 Self Learning（没装会自动跳过） |
| `enable_chatplus_sync` | `true` | 联动 Group Chat Plus 的群情绪（没装会自动跳过） |
| `auto_sync_on_change` | `false` | 记录/查询后自动同步，而不是只在 `经期 同步` 时写 |
| `mood_duration_hours` | `24` | 写入对方的心情持续多久 |
| `enable_reminder` | `false` | 让她在经期前一天、第一天、PMS 段主动说一句；她自己过周期时一般不用开 |
| `reminder_style` | `in_character` | 提醒口吻：她的口吻 / 系统通知口吻 |
| `enable_comfort_buff` | `true` | 识别"倒热水、抱抱"这类关心并折算进状态 |
| `comfort_hours` | `6` | 一次关心生效多久（1–12 小时，越界按类别内置时长） |
| `enable_llm_voice` | `true` | 让模型写文案的总开关 |
| `voice_mode` | `cycle` | `cycle` 每周期写一次 / `realtime` 每次现写 / `off` 不调用 |
| `realtime_injection` | `false` | 实时模式下也让每条消息现写（慢、费） |
| `live_interval` | `25` | 实时生成在这个秒数内复用，0 表示每次真写 |
| `voice_timeout` | `20` | 生成文案的等待上限（秒），超时改用内置文案 |
| `reminder_check_minutes` | `20` | 检查间隔 |
| `reminder_hour_from` / `to` | `9` / `23` | 允许提醒的时段，避免半夜吵人 |
| `default_cycle_length` | `28` | 样本不足时的兜底周期 |
| `default_period_length` | `5` | 兜底经期长度 |
| `default_cycle_day` | `0` | 第一次替她建档时落在第几天；`0` 表示随机挑一天 |
| `default_pain_sensitivity` | `1.0` | 新建档案的疼痛敏感度（0.2–2.5） |
| `default_emotion_gain` | `1.0` | 新建档案的情绪幅度（0.2–2.5） |
| `default_pms_strength` | `1.0` | 新建档案的 PMS 强度（0–3，`0` 等于没有经前期） |
| `remember_session` | `true` | 记住最近会话，用于主动推送 |
| `enable_dashboard` | `true` | 注册面板页面与接口；关掉只是不显示入口 |
| `enable_admin_only` | `true` | 只有 AstrBot 的管理员能用指令与记录工具 |
| `extra_admins` | 空 | 补充的管理员 ID，逗号分隔；不想改全局 `admins_id` 时用 |
| `admin_deny_reply` | `true` | 非管理员发指令时回一句说明；关掉则完全不吭声 |

主动提醒只在几种日子发：经期前一天、经期第一天、PMS 开始、经期快结束，以及排卵日那天（"今天状态好得有点离谱，突然想见你"）。默认用**她自己的口吻**说，不是健康 App 的通知；想要后者可以在配置里切，或 `经期 提醒 口吻 系统`。同一个周期里同类提醒只发一次，不会在 PMS 那几天天天念叨；每个用户都能用 `经期 提醒 关` 关掉。

## 面板

AstrBot 后台 → 插件 → 生理周期 → **页面**，能看到所有人的这一轮，不用在群里发命令。

左边是档案列表（按最近活跃排序，带阶段色点、"刚被哄过"角标），右边是选中那个人的全部细节：

> 默认（`cycle_scope=character`）打开面板就是她一个，天数、阶段、下次时间都已经在算了——不需要谁去建档案。
> 切到 `user` 模式时，面板才会按人分开；那时左下角会有 **＋ 新建档案**：选平台、填用户 ID、昵称，
> 顺手把最近一次的开始日填上，不用等对方先在群里说一句话。

| 区块 | 内容 |
| --- | --- |
| 顶部 | 阶段、第几天 / 总长、一句话状态、距下次天数、进度条（第一天 → 下次） |
| 四条数值 | 疼痛、愉悦、压力、精力，和注入给模型的是同一份数据 |
| 三个卡片 | 身体感受、此刻的倾向（她的行为倾向）、统计（记录数、中位周期、经期长度、最近三次、提醒口吻） |
| 她的状态 | 改当下的状态：自报疼痛、补一次"被照顾"、校正今天算第几天、开关观察期 |
| 最近 7 天 | 疼痛与心情的走势曲线（红线＝疼，绿线＝心情），回看的那几天按推算，今天这一点会跟着钉住的数值走 |
| 记录 | 每次经期的开始/结束/时长/备注；行内**编辑**、**删除**，右上角"记今天开始 / 记今天结束 / 补录一条" |
| 设置 | 她的名字、最近一次开始日、周期长度、经期长度、疼痛敏感度、情绪幅度、PMS 强度、提醒口吻、观察期到哪天、主动提醒 |
| 直接钉住情绪数值 | 八维（愉悦/唤起/精力/压力/疼痛/敏感/亲密/社交）逐项覆盖，带有效时长 |
| 她要看到的那段话 | 直接把这次注入给模型的系统提示词原文摊开，逐字可核对 |
| 这一轮的说法 | 当前用的是模型写的还是内置的，一个"重写这一轮"按钮 |

### 她只有一条

`cycle_scope=character` 时，面板里就是她一个，没有「新建档案」——本来也不需要：她第一次被用到时，插件已经替她把这一轮接上了。
想改她的开始日、补一段过去的记录、或者校正今天算第几天，都在右边的「她的状态」和记录表里直接改。

### 改写历史

"补录一条"是给刚开始用的人准备的：把过去几个月的经期按日期填进去，周期长度立刻按历史算，不用等三个月。点某一行右侧的**编辑**，那行会就地变成日期和备注输入框，保存即写盘。

日期一律在这里校验：不能填未来、结束不能早于开始、一次不超过 15 天、不能和已有记录重叠（重叠会告诉你是跟哪天那条撞了）。补录和编辑都会重新排序，并让这一轮的模型文案失效重写。

### 改当下的状态

四个快捷操作，效果和她在群里自己说一样：

| 操作 | 对应命令 | 效果 |
| --- | --- | --- |
| 今天有多疼 0–10 | `疼 7` | 自报值按 82% 权重盖过曲线推算，同时压低精力、抬高压力 |
| 刚被照顾了一次 | 他递热水 / 抱一下 | 按类别加一条有时效的安抚，疼痛和压力当场下降，最多同时 12 条 |
| 今天算第几天 | — | 只挪最近一次的起始日，不新增记录（记错了、忘了记都能救） |
| 观察期 | `暂停 30` / `恢复` | 暂停期间不做精确推算、不发提醒，注入换成"先不报天数"的说法 |

被照顾那一条可以选类别（止痛药 / 热的 / 揉揉 / 抱抱 / 让她歇着 / 吃的）和时长（0.5–24 小时），默认用该类别的标准时长；"全部清掉"会把所有还在生效的安抚一次清空。

改完立刻生效——写的是同一份 `cycles.json`，下一次回复注入的就是新值；开了自动同步时，还会顺手把新情绪推给 Self Learning 与 Group Chat Plus，不用重启插件，也不用等缓存过期。

### 管理员能改到哪一层

面板不是只读的。除了改记录和快捷状态，这两层也能直接动：

| 想做的事 | 在面板哪里 | 说明 |
| --- | --- | --- |
| 改她的名字 | 设置 → 她的名字 | 留空就叫「她」；同时会写进注入里的称呼 |
| 挪整条周期 | 设置 → 最近一次开始日 | 等于把这一轮整体往前/往后挪，聊天侧下一句就按新天数算 |
| 改身体参数 | 设置 → 周期长度 / 经期长度 / 疼痛敏感度 / 情绪幅度 / PMS 强度 | 带范围校验，越界会告诉你合法区间 |
| 改提醒方式 | 设置 → 提醒口吻 / 主动提醒 / 观察期到哪天 | 口吻是"她的口吻"或"系统通知" |
| 钉住某一维情绪 | 她的状态 → 直接钉住情绪数值 | 八维任填，0.5–168 小时内有效；填了就以你为准，到期自动回到周期推算 |
| 看她实际被注入了什么 | 她要看到的那段话 | 就是拼进系统提示词的那段原文，含身体、情绪、此刻倾向、硬性规则 |

钉住的优先级高于自报疼痛、高于被照顾、高于周期曲线——适合演特殊剧情（大出血、失恋、病中），也适合临时把某一天的情绪拉平。清掉即恢复：`恢复推算` 会立刻回到八维曲线。

接口（都在插件名下，鉴权跟随 Dashboard 登录，插件自己不做账号体系）：

| 路由 | 方法 | 作用 |
| --- | --- | --- |
| `/astrbot_plugin_menstrual_cycle/overview` | GET | 所有人概览 + 插件状态 + 平台列表 |
| `/astrbot_plugin_menstrual_cycle/user` | POST | 新建档案（`platform` / `sender` / `nickname` / `start`） |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>` | GET | 单个人详情 |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>/record` | POST | `start` / `end` / `delete` / `create`（补录）/ `update`（改写） |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>/state` | POST | `pain` / `comfort` / `cycle_day` / `pause` / `overrides`（八维钉住） |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>/settings` | POST | 改设置（带范围校验） |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>/voice` | POST | 重写或清掉这一轮的文案 |
| `/astrbot_plugin_menstrual_cycle/user/<path:user_key>/reset` | POST | 清空某个人的数据 |
| `/astrbot_plugin_menstrual_cycle/detail` | GET | 同「单个人详情」，但 `user_key` 走 query：`?key=character:self` |
| `/astrbot_plugin_menstrual_cycle/action` | POST | 统一写入口：body 里 `key` + `op`（`record`/`state`/`settings`/`voice`/`reset`），其余字段同对应接口 |

写接口都返回 `{ok, message, detail}`，`detail` 就是最新的整份详情，前端直接拿来回渲，不用再请求一次。

面板默认走 `/detail` 和 `/action` 这一对：`user_key` 里有冒号（默认档案就是 `character:self`），放进路径时不同版本的网关和反向代理处理得不一样，放进 query 或 body 就完全没这个问题。路径版接口还留着，方便脚本直接调，也对旧前端兼容。

页面是原生 JS，没有构建步骤，明暗主题跟随 Dashboard（`data-theme`）。文件在 `views/dashboard/` 下：`index.html`、`app.js`、`style.css`。改静态资源刷新页面即可，新增视图目录才需要重载插件。把 `enable_dashboard` 关掉，接口和入口都不再注册。

## 让模型自己写这一轮的话

内置文案写得再细，说多了也会眼熟。这个插件可以把你配的**对话模型**接进来，让她这一轮的说法由模型现写。三种模式（`voice_mode`）：

| 模式 | 什么时候调模型 | 适合 |
| --- | --- | --- |
| `cycle`（默认） | 每个周期一次，五个阶段整套写下来，整轮复用 | 想省钱又要变化 |
| `realtime` | 查状态、发提醒时**现场写**这一句（默认 25 秒内复用，避免一句话触发好几次） | 想让她每次都不一样 |
| `off` | 不调用，全用内置文案 | 不想花这个钱 |

`realtime` 下还有 `realtime_injection`：打开后**每条消息**都会多一次模型调用（注入里的状态卡也现写），回复会明显变慢、成本按消息数增长，所以默认关。只想要提醒和查询实时，保持关闭即可。

`cycle` 模式下写的是这 10 个槽位：

| 槽位 | 用在哪 |
| --- | --- |
| 五个阶段的 `name` | 状态卡的标题，比如「最不好惹的那几天」 |
| 五个阶段的 `body` | 「身体：」那一行，第一人称、具体到部位 |
| 五个阶段的 `mood` | 「情绪：」那一行，像她自己说，而不是形容她 |
| 五个阶段的 `behaviors` | 「她现在的样子」和注入里的「此刻的倾向」，决定她怎么说话 |
| 五条 `reminders` | 主动提醒的那一句，`{days}` 会换成真实天数 |

`realtime` 模式只写**当前阶段**这一套（名字 / 身体 / 情绪 / 三条反应 / 一句想说的话），并把对方刚说的那句话一起给它，所以她的反应能接得上；这里不落盘，只在内存里放 `live_interval` 秒。

怎么算「同一个周期」（`cycle` 模式）：签名 = `最近一次记录的起点 + 已经滚过的轮数`。所以

- 记了新的第一天 → 签名变 → 下次查询时自动写新的一版
- 周期滚过一整轮（比如中间漏记了）→ 签名也会变
- 同一轮里查一百次 → 只生成一次，之后都读缓存

什么时候生成（`cycle`）：

- `经期 状态`、或模型自己调 `period_cycle` 查状态时，有缓存直接用；没有就先用内置文案回话，同时在**后台**写，写完下次查询自动生效（不阻塞对话）
- `经期 开始` 记新周期时，顺手把旧文案作废并后台重写
- `经期 文案 写` 立刻重写并等结果（十几秒），想当场看到就用这个
- 主动提醒发出前若这一轮还没写，就先按内置的发，不会为了等文案错过时点

`realtime` 下 `经期 文案 写` 是强制再写一次（忽略 25 秒窗口），`经期 文案` 会告诉你当前是哪种模式、上一次现写是几点。

失败怎么办：超时（默认 20 秒）、模型答非所问、JSON 坏了、有效阶段少于两个——一律当这次没写成，继续用内置文案，并在 `经期 文案` 里告诉你原因。不会因为模型抽风把状态卡搞空。

写出来的东西会被清洗：压成一行、去掉「激素 / 内分泌 / 医学 / 插件」这类词；`body` ≤ 72 字、`mood` ≤ 28 字、每条行为 ≤ 56 字、提醒 ≤ 140 字。超了截断，不报错。

缓存位置：`voice_cache.json`（仅 `cycle` 模式，按用户 + 签名存，原子写）。`经期 文案 清` 只丢当前这一轮。

成本：`cycle` 一个用户一个月大约 1 次；`realtime` 大约等于「查状态次数 + 提醒次数」，注入默认不计入。

不想花这个钱就把 `voice_mode` 设成 `off`——内置文案本身也有每阶段 6 条素材轮换（同一天固定，跨天会变）。

## 她的状态是怎么被改的

周期曲线只是底子。真实感来自三件会盖在它上面的事：

**一、她自己的话优先。** `经期 疼 7` 记下今天的实际疼痛，按 82% 的权重压过曲线（留 18% 让曲线仍有影响），并顺带把情绪往下压——疼得厉害的人不会心情好。第二天不写就自动回到曲线。

**二、被照顾会真的缓下来。** 六类关心，各降不同的量，按优先级匹配：

| 类别 | 触发词示例 | 主要作用 | 时长 |
| --- | --- | --- | --- |
| 药 | 布洛芬、止痛药、暖宝宝、暖宫贴 | 疼痛 −0.26，精力 +0.05 | 8 小时 |
| 热 | 热水、红糖、姜茶、热水袋、热敷 | 疼痛 −0.16，压力 −0.13，愉悦 +0.10 | 6 小时 |
| 揉 | 揉揉、按按、捏捏、摸摸头 | 疼痛 −0.15，社交欲 +0.09 | 5 小时 |
| 抱 | 抱抱、搂、贴贴、蹭蹭 | 压力 −0.17，愉悦 +0.15，社交欲 +0.13 | 5 小时 |
| 担 | 你去躺着、我来、别动、早点睡 | 压力 −0.19，愉悦 +0.12 | 7 小时 |
| 吃 | 吃饭、煮点、粥、巧克力、宵夜 | 愉悦 +0.10，精力 +0.07 | 5 小时 |

否定词（不、别、没、懒得……）会否掉整个片段，"别喝热水了"不算关心；同类 90 分钟内不重复计，不同类可以叠加，但第二件同类只按 62% 递减计——被哄两次不会是两倍效果。注入里会多一句"他刚照顾过你：别反复追问『好点没』，也别拿这件事讨功"，这是很多人会犯的错。

**三、周期本身可能不准。** 最近 8 个周期的差值算出 MAD，波动 ≥9% 或极差 ≥10 天就标记"最近不太规律"，然后状态卡里不再报死天数，注入里写明"不能当铁律"。`经期 暂停 30` 进入观察期，期间只描述当下、不推算下次、不发提醒——怀孕、哺乳、用药、多囊都该走这条路，而不是硬套 28 天。

## 与 Self Learning 的联动

Self Learning 没有对外开放的情绪 API，所以这里做三层，逐层降级：

1. **读**（`pull`）：`star_cls.affection_manager.get_current_mood(group_id)` 拿到对方此刻真实心情，连同本插件周期状态一起注入提示词。她的"今天有点烦"和对方的"刚被群里气到"会叠加，而不是互相覆盖。
2. **写**（`push`）：按阶段映射成对方的心情类型，写回它的心情系统——

   | 阶段 | 心情 | 强度 |
   | --- | --- | --- |
   | 月经期 | `SAD` | 0.72 |
   | 卵泡期 | `HAPPY` | 0.62 |
   | 排卵期 | `PLAYFUL` | 0.70 |
   | 黄体期 | `ANXIOUS` | 0.60 |
   | 经前期 | `ANGRY`（唤醒度低时改 `SAD`） | 0.75 |

   强度再按当天的压力与疼痛微调，限制在 0.25–0.95。写入走对方私有的 `_set_immediate_mood`；拿不到就反射构造 `BotMood` + `db_manager.save_bot_mood` + 刷内存缓存（和它自己的 `/set_mood` 同一条路径）。
3. **兜底**：无论前两步成功与否，都会把快照写到 `plugin_data/astrbot_plugin_menstrual_cycle/emotion_snapshot.json`，供别的插件或你自己的脚本读取，也方便排查"为什么今天没反应"。

对方不在、版本对不上、私有方法改名——都会被 `try/except` 接住，只降级不报错，绝不影响主对话。用 `经期 状态` 里的联动行或日志里的 `selflearn` 前缀可以看当前是第几层生效。

> 提示：Self Learning 自己的 LLM Hook 里把 `include_mood` 写死为 `false`，它是靠改人格来做情绪的。想让本插件的周期情绪真正进到对方人格里，需要开启它的 `temporary_persona_updater`；否则走第 1 层的提示词注入也一样有效果。

## 另外两个插件

**Group Chat Plus** 有一套真情绪，但和 Self Learning 不同构：`utils/mood_tracker.py` 的 `MoodTracker` 是纯内存字典，按会话存 `{mood: "开心", intensity: 0.7, last_update: 时间戳}`，方法全是同步的。本插件直接写它的 `moods[chat_id]` 并刷新 `last_update`（不用 `update_mood_from_context`，那个是从聊天文本里抽情绪，不适合指定值），之后它的衰减逻辑会照常接管。阶段映射：

| 阶段 | 写入情绪 | 强度 |
| --- | --- | --- |
| 月经期 | 难过 | 0.70 |
| 卵泡期 | 开心 | 0.55 |
| 排卵期 | 开心 | 0.72 |
| 黄体期 | 平静 | 0.45 |
| 经前期 | 生气（压力 > 0.6 时） | 0.70 |

用 `enable_chatplus_sync` 开关，关闭后完全不碰对方。它的 `MoodTracker` 实例没有公开属性名，这里用 `isinstance` 在插件对象上探测，改名也能找到。

**LivingMemory** 没有情绪层——它只有记忆检索和用户档案（`search_memories` / `profile_manager`），`sentiment` 只是记忆条目的元数据标注。想让它参与，只有两条缝：检索时把情绪线索写进 query，或者 `PromptManager.update_prompt("memory_injection_header", ...)` 改注入头。后者是全局改动、按会话改不了，所以本插件**默认不动它**，把周期状态交给提示词注入更可控。如果哪天需要，`core/` 里的写法可以直接照抄 `ChatPlusBridge` 探测那套。

## 数据

全部落在 AstrBot 的 `data/plugin_data/astrbot_plugin_menstrual_cycle/`：

| 文件 | 内容 |
| --- | --- |
| `cycles.json` | 所有用户的周期记录与设置（原子写，坏文件自动备份为 `.broken.<时间戳>.json`） |
| `emotion_snapshot.json` | 最近一次联动快照 |
| `voice_cache.json` | 模型写的这一轮文案，按 用户 + 周期签名 存 |
| `reminders.json` | 提醒发送记录：`sent` 是当天发过没，`phase` 是这个周期里发过哪一类，重启后不会重复念 |

插件更新、重装都不会碰这个目录。删数据用 `经期 重置`，或直接删目录。

面板上「最近 7 天」里，只有今天那一点用你钉住的数值，前几天按周期推算——手动覆盖的意思是「从现在起这几小时」，不会把过去也一起改写。

## 隐私

周期数据是个人健康信息。本插件不联网、不上报、不带任何遥测；`cycles.json` 只在本地磁盘，除非你自己把它同步出去。清理时用 `经期 重置` 会真的从文件里删掉，不留墓碑。

## 常见问题

**面板打开是空的，右边只有月亮**

`character` 模式下面板一打开就会替她建档，还是空的说明插件没真正加载——看日志有没有 `[menstrual] 已启动`，以及 `data/plugin_data/astrbot_plugin_menstrual_cycle/` 有没有被创建。`user` 模式下档案来自聊天记录，没说过话就确实没有。

**她从来不提生理期的事**

这是设计如此：状态卡是背景，不是台词。先看面板「她要看到的那段话」确认注入有内容，再检查 `enable_llm_injection` 是否被关掉，最后才怀疑模型不理会系统提示词——小模型经常会。

**提醒一直不发**

三个前提缺一不可：`enable_reminder` 打开、她不在观察期、当前时间落在 `reminder_hour_from`–`reminder_hour_to` 之间。另外同一个周期里同类提醒只发一次（重启后也记得），所以第一天发过之后不会再念。

**模型写的文案没换**

`cycle` 模式下**一个周期只写一次**。改完设置还是旧说法，先 `经期 文案 清` 再 `经期 文案 写`。`realtime` 模式每次现场写，失败会静默回落内置，错误原因在面板「这一轮的说法」里。

**天数看起来不对**

第几天 = 距**最近一次开始日**的天数对周期长度取模。漏记一次开始日会整体偏一天以上，用 `经期 开始 11-08` 补一条（管理员），或者面板里直接改「最近一次开始日」。

**面板上传 zip 报 `FileNotFoundError`**

拿到的是旧版「带顶层目录」的包。换扁平包（`metadata.yaml`、`main.py` 直接在压缩包根）。实在不行直接解压进 `data/plugins/`。

**换电脑/重装后数据还在吗**

在 `data/plugin_data/astrbot_plugin_menstrual_cycle/`，插件更新不碰它。迁移就复制这个目录。
